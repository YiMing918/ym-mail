# 佲的邮箱 · 正式版（ym-mail）

多用户域名邮箱系统，跑在 Cloudflare 全免费额度上：**游客不用注册就能用临时邮箱收验证码，注册用户认领地址后锁定私有**，全部规则（谁能用哪个域名、能建几个、能不能删、保留多少天）由站长在独立后台 `/admin` 里定。

- 收信：Email Routing catch-all → Worker 解析入库 D1，**验证码在收信时就提取好**
- 发信：Resend（免费 100 封/天；注册验证码也走它）
- 会话：存 D1（不用 KV —— KV 写额度是全账号最紧的一档，这套系统一根手指都不碰它）
- 页面：静态资源托管，打开页面不消耗 Worker 请求额度

---

## 部署清单（从零到上线）

> 前提：一个 Cloudflare 账号、要用的域名、一个 Resend 账号。代码本身账号无关，部署到哪个账号都行；域名必须先作为 zone 存在于**同一个**账号里（Email Routing 跟着域名走，跨账号接不到信）。

### 1. 准备代码与依赖
```bash
npm install
cp wrangler.toml.example wrangler.toml
```

### 2. 建 D1 并初始化
```bash
npx wrangler d1 create ym-mail-db     # 把输出的 database_id 填进 wrangler.toml
npm run db:init                        # 远程建表（= wrangler d1 execute --remote --file=./schema.sql）
```

### 3. 设置 Secret（不要写进任何文件）
```bash
npx wrangler secret put ADMIN_USER            # 后台管理员账号，自己定
npm run hash -- '你的管理员密码'               # 生成 PBKDF2 哈希
npx wrangler secret put ADMIN_PASSWORD_HASH   # 把上一步的输出粘进去
npx wrangler secret put RESEND_API_KEY        # 发信要用；暂时不发信可跳过（发码/发信会返回明确报错，不崩）
# 可选（Telegram 推送）：
npx wrangler secret put TG_BOT_TOKEN
# TG_CHAT_ID 是普通变量，写在 wrangler.toml 的 [vars] 里
```

### 4. 部署 Worker
```bash
npx wrangler deploy
```
记下分配的地址（如 `ym-mail.<你的子域>.workers.dev`）。想用自己的域名访问，把它在 Cloudflare 控制台绑定为该 Worker 的自定义域（Workers → ym-mail → 设置 → 域和路由 → 添加自定义域）。

### 5. 每个邮箱域名开 Email Routing（每个域名都要做一遍）
在 Cloudflare 控制台选中该域名 → **Email（电子邮件）→ Email Routing**：
1. 启用 Email Routing（它会自动加好 MX/TXT 记录）；
2. 「目标地址」里添加并**验证**站长自己的常用邮箱（备份转发要用；验证邮件点一下链接即可）；
3. 「路由规则」→ **Catch-all** → 操作选 **发送到 Worker** → 选 `ym-mail` → 保存。

> 域名如果是在别家注册的，需要先把 NS 授权到这个 Cloudflare 账号、成为 zone，才能开 Email Routing。

### 6. 在 Resend 验证发信域名（发码/发信前必做）
Resend 控制台 → Domains → 添加发信域名 → 按提示加 DKIM/SPF 记录（加在 Cloudflare DNS 里）→ 等状态变成 Verified。不验证的话 Resend 会拒发，接口会把拒绝原因原样提示出来。
**注意：发信域名必须是自己注册的域名**——免费公共后缀的域名（免费领的二级域名）会被 Resend 直接拒绝。收信域名可以和发信域名不是同一个：比如收信用免费域名、发信用自己买的域名的子域名（mail.你的域名），在后台「系统发件地址」里填子域名下的地址即可。

### 7. 管理员初始化
1. 打开 `https://<你的地址>/admin`，用第 3 步的管理员账号密码登录；
2. 在「域名政策」里**添加你的域名**（第一个添加的自动成为主域名，不可删除）；
3. 按需要调政策：哪个域名开放给注册用户/游客、各自能建几个、游客保留天数、注册方式（默认邮箱验证）等；
4. 回到前台，用你自己的常用邮箱**注册第一个账号** —— 系统会自动把第一个注册账号标记为站长账号（不受个数/位数政策限制）。**第一个账号不需要邀请码、也不需要邮箱验证码**，任何注册方式（包括关闭注册）都不会挡第一个账号——这是故意的，保证刚部署完没人会被自己的注册门锁在外面；从第二个账号开始，注册方式才按后台设置生效。邀请码只有一个输入框：填站长发的注册码 = 直接注册、只享政策额度；填已注册用户的个人邀请码 = 也能注册，且邀请人得专属额度（开关和个数在后台）。认领你自己的主地址后，在 D1 里把它的 `protected` 置 1 可防误删：
   ```sql
   UPDATE addresses SET protected = 1 WHERE address = '你的主地址';
   ```
5. 备份转发还差一步：每个开了备份转发的用户，其**注册邮箱**都要先在 Email Routing 的「目标地址」里验证过，转发才会成功（未验证时只会在日志里失败，不影响收信入库）。

### 8. 上线自检
- [ ] 往任意地址（如 test@你的域名）发一封带验证码的测试信 → 前台能看到、验证码自动提取
- [ ] 游客模式：不登录能生成临时地址、能看公开邮件
- [ ] 注册一遍（邮箱验证码能收到 / 邀请码能用）
- [ ] 认领一个公开地址 → 退出登录后看不到它的信
- [ ] 后台改一条政策 → 前台额度条立刻变
- [ ] 第二天看一眼 cron 有没有按保留天数清理（或等几天抽查）

## 免费额度全清单（都是什么、有多少、超了会怎样、这套系统怎么花）

这套系统只用四家的免费额度：Cloudflare Workers、D1、Email Routing、Resend。先说清一个大前提：**Cloudflare 的免费额度大多是「账号级」的——同一个账号下所有 Worker/D1 共用一池**，所以本站建议部署在一个相对空闲的账号里，别和一堆高频项目挤。另外所有「每天」的额度都在 **UTC 0 点（北京时间早上 8 点）重置**。

### 1. Workers 请求：100,000 次/天（账号级）

- **干啥的**：每调用一次 Worker 算一次。本站的页面是静态资源（不算，见第 3 条），只有接口调用算：打开站点拉一次首屏数据、点开一封信、登录、注册、建地址等。
- **超了会怎样**：当天的新请求直接报错（不会扣费，免费版没有超量付费这一说），第二天早上 8 点恢复。
- **本站怎么省**：首屏把数据打包成一次请求；列表只拉摘要、正文点开才拉；30 秒一次的自动刷新只问一句「有没有新信」（一条聚合查询），没新信就不拉列表。一个人正常用，一天也就几百次请求；10 万次够几百个活跃用户。

### 2. Workers CPU：10 毫秒/次请求（免费版）

- **干啥的**：每次请求里代码真正算题的时间（等数据库、等网络不算）。
- **超了会怎样**：这次请求失败。本站最重的活是收信时解析邮件正文 + 正则提验证码，都是毫秒内的小活，离上限很远。

### 3. Workers 静态资源：免费不限量

- **干啥的**：本站的前台页面、后台页面、样式和脚本都走静态托管，打开页面本身**不占**上面 10 万次请求额度。这是本站能「随便刷」的原因——贵的是接口调用，不是看页面。

### 4. D1 读：5,000,000 行/天（账号级）

- **干啥的**：数据库查询扫到多少行算多少行。本站所有数据——用户、地址、邮件、会话、设置、政策——都在 D1 里（见第 6 条为什么不用 KV）。
- **超了会怎样**：当天查询报错，次日恢复。
- **本站怎么省**：列表查询只取摘要列且分页（一页 30 条）；设置/政策/黑名单在进程内缓存 60 秒，收信和接口不反复查；自动刷新用一条聚合 SQL 拿全站未读数，不逐箱数。

### 5. D1 写：100,000 行/天 + 存储 5 GB（账号级）

- **干啥的**：每插入/更新/删除一行算一次写。收信最花写：一封信 = 邮件 1 行 + 每个附件 1 行 + 地址活跃时间更新 1 次；登录写 1 行会话；注册写 1 行用户。
- **超了会怎样**：当天写不进去（收信会失败重试、注册会报错），次日恢复；存储满了同样写不进，靠每天的自动清理腾地方（见「自动清理机制」一节）。
- **本站怎么省**：正文最多存 10 万字；附件单个 ≤512KB 才存（大的只留文件名）；黑名单/被封地址的信在写库之前就拦掉，一行都不写。

### 6. KV：本站**完全不用**（这条是故意写给部署者看的）

- **为什么躲着它**：KV 免费版每天只有 **1,000 次写（账号级，所有项目共用）**，是 Cloudflare 全家桶里最紧的额度。很多同类项目把会话、计数器放 KV，几百个用户就能写爆，还连累同账号的其他项目。
- **本站的做法**：会话、设置、验证码、限流计数全部放 D1（写额度 10 万/天，是 KV 的 100 倍），从根上避开这个坑。

### 7. Email Routing（收信通道）：免费，无公布的每日收信量上限

- **干啥的**：负责把发到你域名任意地址的信转给 Worker。本站每个域名只占一条 catch-all（全域接收）。
- **相关的量**：每个域名最多 200 条普通路由规则（catch-all 不占这个数）；**每个账号最多 200 个「已验证目标地址」**——本站的「Gmail 备份转发」就是往用户注册邮箱转发，目标地址要先在账号里验证过，200 个封顶，意味着靠转发备份的用户最多约 200 人（站内收信本身不受这个限制）；单封邮件上限 25 MB，超了对方会收到退信。

### 8. 定时任务（Cron）：免费

- 本站每天只跑 **1 次**（UTC 19:15 = 北京时间凌晨 03:15），一次批量做完全部清理，不额外花什么额度。清理细则见下一节。

### 9. Resend（发信通道）：100 封/天，3,000 封/月

- **干啥的**：本站自己不能发信（Email Routing 只收不发），注册验证码和用户发信都经 Resend 发出。
- **超了会怎样**：当天/当月发不出，注册的人收不到验证码。这是全系统最先见底的一项，人多了先升它或换通道。
- **一个大坑（实测）**：Resend 的发信域名**必须是自己注册的域名**，免费公共后缀域名（各种免费领的二级域名，如 `.us.ci`、`.eu.cc` 这类）会被直接拒绝（"We don't allow free public domains"）。所以：**收信域名可以用免费域名，发信域名请用自己买的正经域名**（用它的子域名也行，如 mail.你的域名，不影响主域名现有服务）。

### 10. GitHub Actions（自动部署）：公开仓库免费不限量

- 推代码自动部署靠它。公开仓库的标准运行器免费不限分钟数；私有仓库免费版每月 2,000 分钟（一次部署约 40 秒，怎么都够）。本站仓库是公开的，不用管这项。

### 自查方法

- 请求数：Cloudflare 控制台 → Workers & Pages → 用量；
- D1 读写量：控制台 → D1 → 选库 → Metrics；
- 站内规模：邮箱后台顶部有用户数 / 邮箱数 / 今日收信三个数；
- Resend 用量：Resend 控制台首页直接显示当月已发/剩余。

## 自动清理机制（清什么、按什么规矩、在哪改）

每天北京时间凌晨 03:15 自动跑一次，一批批量 SQL 做完下面全部清理。**所有天数都是站长在后台自己填的数字**，下面写的是默认值和规则：

| 清什么 | 规则 | 在哪改 |
|---|---|---|
| 游客的邮件 | 超过「游客保留天数」（默认 1 天）的全删，附件一起删；游客没有星标豁免 | 后台 → 全站开关 → 游客保留天数 |
| 注册用户的邮件 | 按**每个用户自己选**的保留天数删（在他的个人设置里选）；站长设的「最长保留」封顶：用户选了永久或超过上限的，一律按上限算；**星标邮件永不删**；附件随邮件一起删 | 后台 → 保留与清理 → 注册用户最长保留（默认上限 180 天） |
| 闲置的**随机**地址 | 随机地址超过「闲置清理天数」（默认 7 天）没收到新信 → 地址连同它的全部邮件、附件一起删，名额自动返还；用专属额度建的随机地址被清时，**专属额度退回主人**；**自定义地址永不被这条清** | 后台 → 域名政策/清理设置 → 随机地址闲置清理天数 |
| 过期的注册验证码 | 过期即删（验证码本身 10 分钟有效） | 不用管 |
| 过期的登录会话 | 过期即删 | 不用管 |
| 陈旧的限流记录 | 7 天前的登录失败计数等记录删掉 | 不用管 |

不自动清、需要人工管的：

- **墓碑记录**：用户删掉地址且该域名政策是「删后不返还额度」时，会留一条墓碑继续占着名额（防有人反复删了重建、抢注好名字）——这是故意的，不是垃圾数据；想放行就在后台把该域名的「删掉后返还额度」打开，之后删的就不再占额。
- **黑名单 / 封禁名单**：后台手动加减，不自动过期。
- **已删域名的存量数据**：在后台删域名只是停用，旧地址和旧邮件保留在库里（防误删），重新添加同名域名即恢复。

## 测活与保活

- **测活**：站点是否活着看站长自己的测活总览（ym-dash，每 30 分钟自动探活一次）；部署流水线每次部署后会请求 `/api/bootstrap` 做自检。深层探活标准：`/api/bootstrap` 返回正常 = Worker 与 D1 都通。
- **保活**：Workers / D1 / Email Routing 无休眠、不需要定期登录或请求保活；证书由 Cloudflare 自动续。只需人工盯三件事：邮箱域名到期前续费（免费域名尤其注意，过期可能被直接删除）；Resend 的 API 密钥别误删；GitHub 长期无活动的仓库其定时工作流可能被平台停用（本站部署是推送触发，影响小；每日清理是 Cloudflare Cron，与 GitHub 无关）。

## 它跟同类有什么不同

- **认领锁定**：临时邮箱地址人人可见，但谁注册认领了就变私有（连历史邮件一起锁定），一个系统同时当公开临时邮箱和私人邮箱用。
- **政策细到域名 × 人群 × 地址种类**：每个域名对注册用户/游客分别定自定义与随机的个数、自定义前缀最少位数、能否删除、删后返不返额度。
- **验证码是一等公民**：收信即提取、独立验证码页、TG 推送里直接带码。
- **为免费额度而写**：不用 KV、设置全缓存、列表只拉摘要、清理一天一次批量 SQL。

## 优点

- 全免费跑（Cloudflare 免费额度 + Resend 免费档），无服务器、无月租。
- 部署物只有一个 Worker + 一个 D1 + 静态文件，迁移 = 换账号重跑部署清单。
- 代码与数据分离：仓库里没有任何域名、账号、用户数据；域名全部在后台动态管理。

## 缺点 / 已知限制（使用层面）

- **发信总量受 Resend 免费档限制**（100 封/天）：注册高峰时验证码可能排队，超了当天发不出。
- **发信域名不能用免费公共后缀域名**：Resend 会拒绝（收信不受影响）；发信请用自己注册的域名或其子域名。
- **备份转发有个前置条件**：转发目标（用户注册邮箱）必须先在 Cloudflare Email Routing 的目标地址里人工验证，陌生用户注册后不会自动完成，需要站长协助或用户配合点验证链接；没验证的就只有 TG/站内能看。
- **游客额度是全站共用一池**（和预览一致）：游客把某域名的随机地址占满后，其他游客在该域名就建不了新的，要等闲置清理或站长放宽。
- **HTML 邮件是沙箱 iframe 渲染**：个别排版怪异的营销邮件显示可能不完美；正文过长会截断（10 万字）。
- **附件只存 ≤512KB 的**：大附件只保留文件名信息，正文里会注明未保存。
- **改政策有最长 60 秒的跨实例延迟**：后台改完，本实例立刻生效；其他边缘实例最迟 60 秒内跟上（正常使用无感）。
- **删域名是停用不是清除**：存量地址和邮件保留在库里（防误删丢数据），重新添加同名域名即可恢复可见。

## 本地开发

```bash
npm install
cp wrangler.toml.example wrangler.toml        # database_id 本地可保留占位
# .dev.vars 里写本地用的 ADMIN_USER / ADMIN_PASSWORD_HASH（参考 README 第 3 步生成哈希）
npm run db:init:local
npm run dev                                     # http://localhost:8787，前台与 /admin 都可开
```
本地 `wrangler dev` 不会真的投递邮件（Email Routing 是线上功能）；收信链路的验证方式见 NOTES.md。需要 wrangler 4.x（`run_worker_first` 数组写法）。
